Benchmarks

How many records per second does a Remoc channel get across, compared to serializing them and writing the bytes into a socket yourself?

What is measured

A sender pushes records as fast as it can for five seconds and a receiver reads them. The same transfer runs twice: once over an rch::mpsc channel, and once over a plain TCP connection that serializes the same records with the same codec and frames them itself. That plain connection is the reference every Remoc number is put next to.

With the default postbag codec one record encodes to 64 bytes, so a batch of 1024 records is a 64 KiB message. The channel is configured with four extra transfer channels, which lets it serialize several messages at once (with_parallel(4)).

Bandwidth and round-trip time are emulated in the process, so a slow or distant connection can be measured without one.
Link Bandwidth Round-trip time
LAN 125 MB/s 0 ms
Wi-Fi 12 MB/s 10 ms
LTE 6 MB/s 50 ms
WAN 25 MB/s 100 ms

Measured on a 13th Gen Intel Core i9-13900K running Linux.

Records per second

How much you get through depends on how many records you hand over at once. One panel per link, with the plain TCP reference doing the same serialization.

What Remoc costs

The same runs as a share of what a raw TCP transfer reaches on that link, which is the dotted line. The grey bar is what serializing the records costs; the pink bar adds multiplexing, chunking and flow control on top.

Run it yourself

The suite is part of the repository. It sweeps every layer, codec and link, prints a table per link and writes a JSON report. plot.py draws all of it, plot_web.py draws the two figures above. 

$ cd bench/perf
$ cargo run --release -- --out results.json
$ ./plot.py results.json
$ ./plot_web.py results.json
