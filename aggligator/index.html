Aggligator

Your friendly link aggregator.

Aggligator combines multiple network links between two endpoints into one connection. Data is distributed across the links that are currently usable. If one fails, unacknowledged data is sent again over the others; links can be added and removed while the connection runs. Links may use TCP, TLS, WebSockets, USB, Bluetooth, SOCKS5 or a custom ordered transport.

One connection, many links

Use it like a socket

The TCP transport discovers routes between the two hosts and uses each as a link. Both ends receive a stream implementing AsyncRead and AsyncWrite.

A Connector combines different transport types in the same connection. This client can reach a device over the network and over USB at once.

Features

Capacity follows the links

Faster links become ready for more data sooner and therefore carry more. The distribution changes as link conditions change.

Links can change

Links may fail, return, be added or be removed while the connection runs. If another link remains available, unacknowledged data is sent over it.

Runs in user space

Unlike Multipath TCP or SCTP, Aggligator does not require multipath support from the operating system or network. It runs over ordinary connections.

Bring your own links

An ordered AsyncRead/AsyncWrite stream or a Sink/Stream of packets can be used as a link.

Authenticated link attachment

A secret established with Diffie-Hellman protects the connection identifier used when adding links. Payload data is not encrypted; use TLS for untrusted links.

TLS wrapper →

Per-link statistics

Each link reports latency, throughput and unacknowledged data. Applications can consume the values directly or display them with the terminal monitor.

aggligator-monitor →

Safe Rust on native and WebAssembly

Aggligator contains no unsafe code, runs on Tokio and supports native platforms and WebAssembly.

How traffic is distributed

Aggligator adapts to link capacity and latency while the connection runs. It does not assign a fixed share or depend on a bandwidth estimate.

Ready links receive data

The next packet goes to a link with available send capacity. Faster links become ready sooner and carry a larger share without a calculated split.

Reordering limits a link

Data waiting behind a missing packet is measured directly. When a link causes that backlog to grow, its send allowance is reduced.

Slow links are retested

A link whose latency makes it counterproductive can be set aside. It is tested periodically and used again when its conditions improve.

Links of every kind

Transport crates create links for Aggligator. A connection can combine different transport types.

Additional crates are listed under the aggligator-transport keyword. Custom transports implement the transport API.
Carries links over Crate
TCP, with TLS if you want it aggligator-transport-tcp
WebSockets aggligator-transport-websocket
WebSockets, from a browser aggligator-transport-websocket-web
USB aggligator-transport-usb
WebUSB, from a browser aggligator-transport-webusb
Bluetooth on Linux aggligator-transport-bluer
SOCKS5 proxies aggligator-transport-socks
anything above, wrapped in TLS aggligator-wrapper-tls

Forward TCP ports with agg-tunnel

agg-tunnel forwards TCP ports through an aggregated connection. It can be installed with Cargo or downloaded as a prebuilt binary.
