agg-tunnel

agg-tunnel forwards TCP ports through an Aggligator connection. Applications connect to an ordinary local TCP port; the forwarded traffic uses the available links between the tunnel endpoints.

Quick start

This example forwards SSH on port 22 from server.example to port 2222 on the client. The tunnel itself listens on port 5000.

On the server

agg-tunnel server --tcp 5000 --port 22

On the client

agg-tunnel client --tcp server.example:5000 --port 22:2222

Connect through the tunnel

ssh -p 2222 localhost

Aggligator authenticates links joining an existing connection, but agg-tunnel does not encrypt the forwarded payload. SSH is already encrypted; other protocols need their own encryption when the links are not trusted.

Install it

Release archives contain agg-tunnel and agg-speed. The Linux binaries are statically linked.

Linux x86-64 Linux ARM64 macOS Apple silicon Windows x86-64
$ cargo install aggligator-util

agg-speed measures aggregate and per-link throughput. Command reference →

Port mappings

The server lists permitted targets. The client selects one of those server ports and chooses where to expose it locally. Both options can be repeated.

Side Option Meaning
server --port 22 allow forwarding to local port 22
server --port db.internal:5432 allow forwarding to port 5432 on another host
client --port 22:2222 expose server port 22 as local port 2222

Adding links

The TCP transport tries the usable combinations of local interfaces and resolved server addresses. Repeat --tcp for additional targets. Depending on the build and platform, clients can also add links through SOCKS5 proxies, USB or Bluetooth.

Link monitor

When attached to a terminal, agg-tunnel displays the connection, active port forwards and statistics for each link. Use --no-monitor for plain log output.

Common options

Option Applies to Purpose
--tcp client, server connect to a server target or listen on a TCP port
--port client, server add a local mapping or permit a target
--global client listen on all local interfaces instead of loopback only
--tcp-link-filter client control which local-interface and remote-address pairs become links
--socks client add one link through each SOCKS5 proxy
--usb client add a USB link when supported by the build
--no-monitor client, server write plain status messages instead of the interactive monitor
--cfg global load an Aggligator configuration file
