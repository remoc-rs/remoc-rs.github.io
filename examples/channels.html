Example: Tokio-style mpsc channels over TCP

Two Rust processes exchange a typed channel over one TCP connection. The client asks the server to count, sends an mpsc sender inside the request and reads the resulting sequence from the receiver.

{% include example-tabs.html %}

The client creates the channel after establishing the TCP connection. Its sender is transferred to the server as part of the request, while the client retains the receiver. Remoc carries the channel over the existing connection.

The example uses three crates. counting defines the request type, and the client and server binaries both depend on it.

Tokio compatibility: This uses remoc::rch::mpsc, not tokio::sync::mpsc: Tokio's own endpoints cannot be sent between processes. See replacing a local Tokio channel with a remote channel for the API differences.

Related guide: See multiplexing channels over one TCP connection for how the request and sequence share the socket.

Running the TCP client and server

Clone the repository: 

git clone {{ site.repo }}
cd remoc

Start the server: 

cargo run --manifest-path examples/channels/Cargo.toml -p counting-server

Then, in another terminal, start the client: 

cargo run --manifest-path examples/channels/Cargo.toml -p counting-client
