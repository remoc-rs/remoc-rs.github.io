Example: Rust trait-based RPC returning channels

The server maintains a counter that clients can query, increase and watch. RPC methods return watch and mpsc receivers that keep delivering updates over the same TCP connection after the call returns.

{% include example-tabs.html %}

The #[rtc::remote] attribute generates a client that implements the trait and server types that dispatch calls to the trait implementation. Calling a method on the client runs it on the server and returns its result.

The watch() method returns a watch receiver and count_to_value() an mpsc receiver. Both receivers continue to deliver values after the method call returns.

Without protobuf: The shared Rust trait and Serde types define the interface; no separate Protocol Buffers schema or protoc step is needed. See Rust traits and Serde vs. schema-based RPC for the trade-offs.

Related guides: The server-push guide explains when to return an mpsc channel instead of a watch channel, and the Unix-socket IPC guide explains how to change the transport without changing the service interface.

Running the RPC client and server

Clone the repository: 

git clone {{ site.repo }}
cd remoc

Start the server: 

cargo run --manifest-path examples/rtc/Cargo.toml -p counter-server

Then, in another terminal, start the client: 

cargo run --manifest-path examples/rtc/Cargo.toml -p counter-client
