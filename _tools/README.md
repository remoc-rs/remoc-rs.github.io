# Site tooling

## Preview the site locally

GitHub Pages builds the site with Jekyll, resolving the layout in `_layouts` and the
shared header and footer in `_includes`. Run the same thing locally:

```
jekyll serve --livereload
```

Then open <http://localhost:4000/>. It rebuilds on every save and reloads the open
tab by itself; `_site/` is ignored by git.

Installing it needs Ruby headers, because two of its dependencies are native. On
Fedora, once:

```
sudo dnf install ruby-devel
gem install --user-install jekyll
```

The site uses no plugins, so plain Jekyll renders exactly what GitHub Pages publishes.

## IndexNow

After deploying updated pages, submit the URLs in the published sitemap to IndexNow:

```
python3 _tools/indexnow.py
```

The script checks the local and published IndexNow key before submitting. It uses
the live sitemap, so deploy sitemap changes first. A successful response means the
URLs were received, not that they have been indexed. To print the same URLs for
manual submission without sending them to IndexNow, run:

```
python3 _tools/indexnow.py --list
```

## Search-facing guides

The specialized guides cover distinct questions: remote channels for Tokio-style
mpsc between processes over TCP, IPC for Unix sockets, Windows named pipes and child-process pipes,
multiplexing for sharing one connection, and server push for bidirectional RPC and
client callbacks. The comparison also covers Rust traits and Serde without a
separate protobuf schema.

The homepage describes Remoc as Rust-native RPC: interfaces use Rust traits and Serde
types without a separate schema. Keep specialized guide and example titles focused on
their own subjects rather than repeating this positioning everywhere.

Keep the front-matter title and description, visible headings, and links from the
homepage and example pages consistent with each guide's subject. Reuse the complete
examples under `examples/`; their source listings in `_includes/example-*.html` are
generated by `render_examples.py`, not independent samples to edit by hand.

Regenerate the listings after changing an example in the Remoc checkout:

```
python3 _tools/render_examples.py ../remoc
```

Build with `jekyll build --safe --strict_front_matter` before deploying. Afterwards,
use Search Console and Bing Webmaster Tools to inspect indexing and actual query
impressions. A local build, sitemap submission or IndexNow acceptance cannot verify
or guarantee rankings; search engines must recrawl the deployed pages first.

## Tunnel usage recipes

The `agg-tunnel` page keeps its SSH quick start and adds goal-based recipes for
multiple services, failover, parallel TCP links, SOCKS5 proxies, SSH over Bluetooth,
SSH over USB, and unattended operation. Task shortcuts near the top link directly
to the relevant sections. The install section offers the default Cargo command and
`cargo install aggligator-util --all-features`, labeled Linux-only.
The Bluetooth and USB recipes start with
the direct link; combining it with TCP is a side note. Keep installation details
in the install section and command-line reference, not in the recipes.
Check commands against the CLI in the Aggligator
checkout. Bluetooth requires the `bluer` feature; the client RFCOMM address is
`'[00:11:22:33:44:55]:7'`. USB needs a Linux peripheral-capable server with a UDC;
the client selects its USB serial number, which is the device's hostname.
A server target on another host uses
`host:target_port:server_port`, with the final number acting as the client-requested
identifier. Keep prerequisite and access-control notes beside the relevant examples.

## Copying commands

The base layout loads `copy-commands.js` for all pages. It adds copy buttons to
`pre.cmd > code` blocks and handles the existing `button[data-copy]` installation
buttons. Mark example output with `data-no-copy` on its `pre`; help text without a
`code` child and source listings are not treated as commands. Keep shell prompts
out of command blocks so their contents can be pasted directly into a terminal.
Buttons are hidden without JavaScript or the Clipboard API; copy failures show a
message asking the reader to select and copy the command manually.

## Tunnel command-line reference

Regenerate the reference from the current Aggligator source checkout, not from its
possibly outdated checked-in Markdown documentation:

```
python3 _tools/render_tunnel_cli.py ../aggligator
```

The script builds and runs `agg-tunnel --help` and each subcommand's `--help`
through Cargo with the lockfile, then writes `aggligator/agg-tunnel-cli.html`.
It preserves the plain-text help in preformatted blocks with man-page-style
headings, wrapping long lines without changing their text. Generate on Linux with the build
prerequisites for Bluetooth and USB installed: the explicit `bluer,usb-host,usb-device`
feature set includes all optional transport flags. The page shows the package
version and the Linux-only `cargo install aggligator-util --all-features` command.

Run this before deploying updates to the utility's CLI. To rebuild from current
source and verify the checked-in reference without writing it:

```
python3 _tools/render_tunnel_cli.py ../aggligator --check
```

Do not edit the generated page by hand. Change CLI help in
`aggligator-util/src/bin/agg-tunnel.rs`, or the page wrapper in the generator, then
regenerate and run the strict Jekyll build.

## `plot_web.py` — draw the benchmark figures

Draws the two figures on the benchmarks page into `plots/`, in a light and a dark
variant each. The data comes from the benchmark suite in the Remoc repository, which
writes a JSON report.

The suite sweeps every layer, codec and link, which takes well over an hour. The
website shows one codec and one channel configuration, so the run it needs is much
smaller — three layers, and the default links and message sizes:

```
cd ../remoc/bench/perf
cargo run --release -- \
    --layer raw_tcp,tcp_struct_postbag,mpsc_struct_par4_postbag \
    --out results.json
```

That is about ten minutes. The three layers are the raw TCP transfer every result is
reported against, the plain TCP connection that serializes the same records, and the
`rch::mpsc` channel with four extra transfer channels. Then:

```
cd ../../../remoc-rs.github.io
pip install matplotlib
python3 _tools/plot_web.py ../remoc/bench/perf/results.json
```

Commit the changed SVGs in `plots/` together with any caption you had to update, and
check the numbers quoted on the page still match the plots.

Use `--quick` while iterating on the plots themselves: it shortens every transfer from
five seconds to one, which is noisy but takes about two minutes.

`plot.py`, next to the suite, draws every layer and codec instead and is the one to
use for analysis rather than for the site.
